# Sensible Inhalte vor der Modellübergabe

Branchloom prüft lokal die tatsächlich vorbereiteten Textfelder, bevor ein neuer Karten-Agent, eine Aufgaben- oder Ideendiskussion, ein Workflow-Plan oder ein Wireframe-Vorschlag an die CLI übergeben wird. Bei einem Treffer zeigt die bestehende Fehlermeldung **Feld, Zeile und Kategorie**, aber keinen gefundenen Wert. Der Start wird abgelehnt; bereits gespeicherte Inhalte werden dabei nicht gelöscht. Bearbeite das genannte Feld und starte den Vorgang erneut.

Erkannt werden typische Schlüsselpräfixe, explizite API-Key-Zuweisungen, Private-Key-Blöcke und absolute Benutzerordnerpfade. Relative Projektpfade, `.env.example` und bloße Verweise auf Umgebungsvariablen bleiben nutzbar. Die Prüfung erfasst die übergebenen Ausschnitte, etwa den begrenzten README-Text, und bei einem Agentenstart den Kartenauftrag sowie den freigegebenen Wireframe-Kontext. Sie durchsucht weder alle Dateien eines Projekts noch die spätere, vom Agenten selbst gelesene Umgebung. Auch umbenannte, unbekannte oder anders formatierte Geheimnisse können unerkannt bleiben. Vor einer externen Modellnutzung sollten Karten und Kontext weiterhin bewusst geprüft werden.

`node scripts/check-public.mjs` prüft für einen öffentlichen Push die **gestagten Git-Blobs** und die von `HEAD` erreichbare Historie. Treffer nennen Datei, Zeile und Kategorie; historische Treffer zusätzlich eine gekürzte Blob-ID. Werte werden nicht ausgegeben. Gesperrte Pfade und übergroße historische Blobs haben keine Inhaltszeile. Ein sauberer aktueller Dateistand heilt keinen alten Commit mit geheimem Inhalt: Die Historie muss vor einem öffentlichen Push bereinigt werden. Der Check ist ein konservativer Filter, keine vollständige Datenklassifizierung.
