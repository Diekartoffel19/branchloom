# Branchloom

Branchloom ist eine lokale Windows-App für Ideen, Projekte, Kanban-Boards, CLI-Agenten, Worktrees, Workflows, Browser und verknüpfte Notizen. Das Ziel reicht von der ersten Idee bis zu Design, Review und QA; die [Produktvision](docs/PRODUCT_VISION.md) trennt Wünsche vom tatsächlich Erreichten. Kangentic ist eine wichtige Referenz; [die Paritätsliste](docs/PARITY.md) zeigt offene Funktionen. Der persönliche Jarvis-Assistent und seine Module sind separate Projekte.

## Starten

Voraussetzungen für den Quellstart: Windows 11, Node.js 24 und Git. Falls `npm ci` native Module nicht als fertige Binärdatei beziehen kann, werden Visual Studio Build Tools mit C++-Toolchain benötigt; die [Release-Anleitung](docs/RELEASE.md) beschreibt den portablen CI-Build ohne lokale Quellkompilierung. Für Agenten muss die jeweilige CLI separat installiert und angemeldet sein; **Codex CLI** ist auf dem Entwicklungslaptop geprüft. Spracheingabe ist optional und benötigt Python 3.13 und ein lokales Whisper-Modell.

```powershell
git clone https://github.com/mschr703/branchloom.git
Set-Location branchloom
npm ci
npm run doctor
npm run dev
```

`npm run doctor` meldet fehlende Pflichtkomponenten und gefundene CLI-Dateipfade; es prüft weder Anmeldung noch Modellzugang. Nicht installierte Agenten-CLIs und Spracheingabe sind optional. `npm run dev` kompiliert den Electron-Hauptprozess, startet Vite nur auf `127.0.0.1:5181` und öffnet die Desktop-App. Zum Beenden im Startterminal `Ctrl+C` drücken. Ein Produktionsbuild aus dem Quellcode lässt sich mit `npm run build` erstellen und anschließend mit `npm start` öffnen. Über die Sonne/Mond-Schaltfläche in der Kopfzeile wird das lokal gespeicherte helle oder dunkle Design gewählt. Ein portables Windows-ZIP wird mit `npm run make:win` gebaut; [RELEASE.md](docs/RELEASE.md) beschreibt auch den Download des geprüften CI-Pakets ohne lokale C++-Build-Tools. Ein Installer ist noch nicht vorhanden.

## Erste Arbeitsschritte

1. **Projekt hinzufügen** und einen existierenden absoluten Ordner auswählen. App-Daten liegen unter `%APPDATA%\jarvis-studio` außerhalb des Repositorys. Dieser bestehende Datenordner bleibt beim Namenswechsel erhalten, damit bisherige Projekte weiter sichtbar sind.
2. Im **Board** eine Karte anlegen oder unter **Aufgabe besprechen** mit dem eingestellten Codex-Workflow-Agenten eine [editierbare Mini-Spec](docs/TASK_DISCUSSION.md) erarbeiten und die Karte bewusst übernehmen. Karten lassen sich ziehen oder per **M** und Zielspaltenauswahl mit der Tastatur zwischen Spalten verschieben. Mit den Links-/Rechts-Schaltflächen im Spaltenkopf lässt sich die Spaltenreihenfolge ändern; das Stiftsymbol benennt eine Spalte um, und eine leere unbenutzte Spalte kann nach Bestätigung entfernt werden. Mit den Auf/Ab-Schaltflächen unter einer aktiven Karte lässt sich ihre Reihenfolge in derselben Spalte ändern; die To-Do-Warteschlange übernimmt diese gespeicherte Reihenfolge beim nächsten freien Kartenstart. Auch bei aktiven Such- oder Label-Filtern beziehen sich die Schaltflächen auf die vollständige Spalte. Karten lassen sich suchen und nach Spalte, Archivstatus, [Priorität und Label](docs/BOARD_METADATA.md) filtern. Für mehrere aktive Karten gibt es [bewusste Sammelaktionen](docs/BULK_BOARD.md) zum Verschieben und Archivieren; die Queue muss dafür pausiert sein, und Spaltenagenten starten dabei nicht. Priorität und Labels werden in der Karte bearbeitet; [lokale Dateien](docs/ATTACHMENTS.md) lassen sich bewusst verknüpfen. Archivierte Karten bleiben mit ihrem Verlauf erhalten und können wiederhergestellt werden. Unter jeder Spalte lassen sich [Agent, Modell und Effort](docs/COLUMN_SETTINGS.md) einstellen; Autostart ist zunächst aus.
3. Unter **Agenten** die [lokale CLI-Erkennung](docs/AGENT_DIAGNOSTICS.md) prüfen. Sie trennt gefundene Programme, erfolgreiche Versionsprüfung und Fehler; eine Anmeldung prüft sie nicht. Eine Karte öffnen, Agent wählen und den Lauf starten. Optional kann für diese Sitzung ein [isolierter Git-Worktree](docs/WORKTREES.md) gewählt werden. In der Karte lassen sich sein Git-Stand prüfen und bereits committete Änderungen nach ausdrücklicher Bestätigung per Fast-Forward übernehmen. Bei parallelen laufenden Karten-Agenten prüft das [Konflikt-Radar](docs/CONFLICT_RADAR.md) bei geöffneter laufender Karte regelmäßig und auf Klick gleiche geänderte Git-Pfade oder eine unvollständige Prüfung. Das interaktive Terminal zeigt Live-Ausgabe und erlaubt Tastatur, Eingabe und Stop. Nach einem beendeten Codex-Lauf kann das passende [gespeicherte Gespräch bewusst ausgewählt](docs/SESSION_RESUME.md) werden. Die CLI verwendet ihre eigene Anmeldung; Branchloom speichert keinen API-Schlüssel.
   Für eigene Befehle ohne Karte gibt es den separaten Bereich **Terminal** mit bewusstem [PowerShell-/cmd-Start](docs/COMMAND_TERMINAL.md), Eingabe, Stop und lokalem Verlauf.
4. Unter **Workflows** den globalen Workflow-Agenten mit **Agent, Modell und Effort** einstellen, ein Ziel beschreiben und den Vorschlag prüfen. Erst **Vorschlag übernehmen** legt Karten und einen Entwurf an; **Starten** beginnt die Ausführung. Der Planer unterstützt derzeit nur Codex CLI in einem schreibgeschützten Aufruf. Alternativ Karten und Spaltenroute manuell wählen. [Modell und Effort je Schritt](docs/WORKFLOW_STEPS.md) lassen sich im Entwurf einstellen; leere Felder erben die passenden Spalten- oder Profilwerte. Ein ungestarteter Entwurf lässt sich bearbeiten oder nach Bestätigung löschen, ohne seine Karten zu entfernen. Ein Agentenschritt gilt nur dann als abgeschlossen, wenn der Prozess erfolgreich endet **und** die letzte bereinigte Ausgabezeile `[JARVIS_STEP_DONE]` ist. Ein fehlender Marker oder Fehler pausiert den Ablauf zur Prüfung. Eine [To-Do-Warteschlange](docs/QUEUE.md) kann mit einer bestehenden Workflow-Route ausdrücklich aktiviert werden und Karten nacheinander bearbeiten; die nächsten freien Karten werden vorher angezeigt. Ein blockierter Queue-Ablauf kann nach Prüfung mit Grund ausdrücklich übersprungen werden; ein zweiter Klick setzt die Queue für die nächste Karte fort. Unter **Entscheidungen** zeigt die [erste Decision Inbox](docs/DECISION_INBOX.md) gespeicherte Workflow- und Queue-Pausen und führt zur betroffenen Stelle, ohne selbst einen Lauf zu starten.
5. Im **Whiteboard** [Architekturboxen mit Projektordnern, Dateien oder Karten verknüpfen](docs/WHITEBOARD.md), Positionen speichern und Verbindungen ziehen oder per Tastatur auswählen. **Repo-Struktur vorschlagen** zeigt einen [belegten Git-Index-Vorschlag](docs/REPO_MAP.md), aus dem Boxen erst nach bewusster Auswahl übernommen werden. Die lokale Canvas-Stufe startet keine Agenten; automatische Abhängigkeitsanalyse und Kartenideen sind noch offen.
6. Unter **Memory** Notizen speichern und als sichere Markdown-Vorschau ansehen. `[[Titel einer Notiz]]` erzeugt eine anklickbare Verbindung; Rückverweise und ein Graph zeigen den Zusammenhang. Einzelne `.md`-Dateien lassen sich bewusst importieren oder exportieren. **Vault-Ordner importieren** zeigt vor dem selektiven Import neue und doppelte Notizen; **Alle Notizen exportieren** schreibt nach Ordnerwahl einen neuen Markdown-Unterordner für das aktive Projekt; [Anleitung](docs/MEMORY.md). Diese Memory-Stufe indexiert noch keine Agentengespräche automatisch.
7. Mit **Strg+K** Karten, Workflows, Memory-Notizen und gespeicherte Agentenverläufe im aktiven Projekt suchen. Unter **Aktivität** gespeicherte Läufe, pausierte Workflows und Karten ohne Lauf ansehen; konkrete [Agentenverläufe](docs/ACTIVITY.md) lassen sich öffnen, als Text speichern oder bewusst als Memory-Notiz übernehmen. Ein Quelllink führt von der Notiz zum Lauf zurück. Der **Browser** öffnet Webadressen in isolierten Tabs, stellt die Tab-Adressen nach einem Neustart wieder her und öffnet einen angeklickten Link nach Rechtsklick nur auf ausdrückliche Auswahl in einem neuen Tab; [Berechtigungen und Grenzen](docs/BROWSER.md) sind beschrieben.
8. Einen Trello-Board-Export über **Board → Importieren** zunächst ansehen und ausgewählte Karten bewusst übernehmen. Benannte Trello-Labels werden angezeigt und mitgenommen; Duplikate werden anhand der Trello-ID erkannt. [Importanleitung](docs/IMPORT.md).
9. Für Spracheingabe [die lokale Voice-Einrichtung](docs/VOICE.md) ausführen. Ein kurzer Clip wird offline transkribiert und erscheint vor dem Senden als editierbarer Text.
10. Im linken Workspace-Bereich das aktive Projekt über **Projekt sichern** als lokales JSON-[Projektpaket](docs/PROJECT_PACKAGE.md) exportieren. **Projekt importieren** zeigt vor dem Anlegen eines neuen Projekts eine Vorschau. Die Datei ist nicht verschlüsselt und enthält nur Board, Karten, Notizen und Workflow-Struktur; Agenten und automatische Läufe bleiben beim Import aus.

Workflows und Karten werden in SQLite gespeichert. Wenn die App während eines laufenden Agenten endet, werden dessen Sitzung und der Workflow beim nächsten Start zur Prüfung markiert; Aktionen werden nicht blind erneut ausgeführt. Codex-Gespräche können über den CLI-Picker manuell wieder geöffnet werden; automatische Wiederverbindung und die sichere Fortsetzung einer unterbrochenen Workflow-Aktion gehören noch zur [Zuverlässigkeitsstufe](docs/PARITY.md).

## Prüfen

```powershell
npm run typecheck
npm test
npm run build
npm audit --audit-level=critical
```

Vor einer öffentlichen Veröffentlichung zusätzlich `node scripts/check-public.mjs` auf den gestagten Dateien ausführen. Das Skript sperrt typische Schlüssel, persönliche Benutzerpfade und lokale Datenordner, ohne gefundene Werte auszugeben. Öffentliche Beispiele verwenden synthetische Daten.

## Stand und Grenzen

[STATUS.md](docs/STATUS.md) nennt den tatsächlich geprüften Stand. Die App ist eine frühe Entwicklungsfassung. Kangentic-Funktionen wie weitere Importquellen, Konflikt-Merge und Worktree-Aufräumen, weitere CLI-Adapter, Live-Diktat, kontrollierte Browsersteuerung durch Agenten, Remote-Mobilzugriff und automatische Knowledge-Graph-Indizierung stehen noch auf der [Paritätsliste](docs/PARITY.md). [Produktvision](docs/PRODUCT_VISION.md), [Open-Source-Referenzen](docs/OPEN_SOURCE_REFERENCES.md) und [technische Orientierung](docs/HANDOVER.md) beschreiben Ziel und Einstieg. Der persönliche Jarvis-Assistent und seine privaten Module sind separate Projekte.
